# الهندسة المعمارية

## دورة الطلب والحوكمة

يبدأ العميل بطلب JSON عبر CLI أو خادم `stdio`. يمر الطلب أولاً عبر آلة حالات حوكمة صريحة:

```text
ANALYZING -> PREVIEWING -> SELF_REVIEW -> EXECUTING
     ^                                  |
     |----------- failure --------------|

أي حالة ------------------------------> HALTED
```

لا يمكن لأداة الكتابة أو التنفيذ العمل في `ANALYZING` أو `PREVIEWING` أو `SELF_REVIEW`. يجب استدعاء موافقة صريحة تنقل الجلسة خلال المراحل الثلاث إلى `EXECUTING`. بعد التنفيذ، يُعاد تحليل الفشل قبل أي محاولة جديدة. يوقف النظام الجلسة بعد **ثلاث خطوات تنفيذية متتابعة** أو عند رصد سبب الفشل نفسه مرتين.

## حماية الأوامر

تستخدم السياسة طبقتين مستقلتين:

| الطبقة | الوظيفة |
|---|---|
| Exact argv allowlist | يجب أن يساوي الأمر بعد `shlex.split` أحد الإدخالات كاملاً؛ لا توجد مطابقة substring. |
| Defensive denylist | ترفض أغلفة shell، أوامر رفع الصلاحيات، الحذف، الشبكة، `git push`، والنشر حتى لو أُضيفت إلى allowlist بالخطأ. |

كما تُرفض عوامل shell مثل `&&`, `||`, `;`, `|`, إعادة التوجيه، وعمليات substitution قبل المقارنة. هذا يمنع تحويل إدخال مسموح مثل `pytest` إلى سلسلة أوامر مركبة.

## الأدلة وسجل التدقيق

كل جلسة في SQLite تحتوي على رسائلها، وأحداث الانتقال بين الحالات، وسجل أدلة مستقل. يُصنف كل دليل إلى:

| النوع | المعنى |
|---|---|
| `OBSERVED` | ناتج مباشر من قراءة ملف أو بحث أو أمر منفذ. |
| `INFERRED` | نتيجة تحليلية أو قرار مراجعة مشتق من ملاحظات سابقة. |
| `UNKNOWN` | معلومة غير متحققة أو بيئة لم تتوفر فيها أداة، مثل غياب Termux:API. |

تُحفظ الحمولة بصيغة JSON محدودة، مع وقت الحدث ومصدره، لتسهيل التدقيق وإعادة بناء سبب القرار.

```text
        |
        v

  ANALYZING / PREVIEWING / SELF_REVIEW / EXECUTING / HALTED

        |
        v
Tool Runtime ---> workspace files / subprocess / Termux:API
        |
        +--> SQLite messages + governance_events + evidence
        |
        v

```

## مسارات Termux وproot-distro

يبقى الخادم والواجهة في Termux لأفضل استجابة ممكنة، بينما تُستخدم Debian داخل `proot-distro` لمسارات البناء التي تحتاج إلى glibc أو حزم لينكس قياسية. لا يخلط المشروع بين بادئة Termux ومسارات FHS في Debian، ولا يحاول تثبيت `linux-headers-$(uname -r)` داخل Termux.

## الاستدلال المحلي

يُعد `scripts/build-llama-android.sh` مساراً اختيارياً لبناء llama.cpp لمعمارية `arm64-v8a` عبر Android NDK. يترك اختيار النموذج خارج المستودع، ويوصي بتنسيق GGUF وتكميم Q4_K_M وسياق محدود مثل 4096 رمزاً. لا تُضمّن أوزان النماذج أو مفاتيح المزودين في Git.

## GitHub Actions

تعتمد الأتمتة على إجراءات قابلة للمراجعة: الاختبارات عند التغيير، فحص TODO أسبوعي، تعليق مراجعة على طلبات السحب، وتصنيف أولي للقضايا. صلاحيات كل مهمة محدودة إلى `contents: read` مع `issues: write` أو `pull-requests: write` عند الحاجة. لا تُشغّل محتويات القضايا أو طلبات السحب كأوامر.
